# Opaija Website Finish Plan

## Today Objective

Finish the public website as a conversion-ready first version and make the command center reflect the real content engine: story writing, action art direction, Seedance video generation, Remotion editing, long-form books, and a future paid reader pass.

## Public Website

1. Keep the hero focused on the first Caribbean anime hook.
2. Keep the contest and email capture as the primary conversion path.
3. Use the flipbook as the free lead magnet.
4. Position books as longer products, not four-page samples:
   - 32-48 page digital comic chapters
   - 48-64 page manga chapters
   - 48-72 page coloring books
   - 24-40 page storybooks
   - 64-96 page artbooks
5. Add the Digital Comic Pass section:
   - free founder preview now
   - paid comic pass next
   - collector library later
6. Keep merch as coming soon until Printful or Printify keys are connected.

   - keep Printful/Printify and payment checkout as next blockers

## Provider Roles

- OpenRouter/OpenAI: story, prompts, planning, canon-aware writing.
- ChatGPT/OpenAI image work: approved original character sheets and future style references.
- fal.ai/Seedance: image-to-video and cinematic clips from approved artwork.
- ElevenLabs: narrator and later character voices.
- Remotion: editing, captions, speed ramps, timing, overlays, final exports.
- Resend: founder emails and release list.
- Future Stripe: digital comic pass checkout.
- Future Printful/Printify: merch product drafts.

## Google Storybook Pattern To Study

Google Gemini Storybook is useful as a product pattern: prompt in, illustrated pages, read-aloud narration, sharing, printing, and downloading. Opaija should use the same high-level idea but with longer formats, strict canon memory, brand-safe art reuse, and paid reader access.

## Security/Legal Guardrails

- Never expose API keys in public code, client bundles, screenshots, or GitHub.
- Do not train on or scrape copyrighted action movies without rights.
- Store external references in a reference log before using them.
- Keep user emails server-side and honor consent/unsubscribe requirements.
- Add payment only after webhook verification and access-control checks.
